# Интеграционные тесткейсы для шардированного хранилища

## Инфраструктурные предпосылки
- Мастер-нода слушает на http://localhost:9090
- Storage-ноды на http://localhost:8085, 8086, ... (REST API)
- Storage-ноды должны быть зарегистрированы в мастер-ноде (POST /scheme)
- Клиент стартует и может обращаться к мастер-ноде

## Тест-кейсы

### 1. Health Check
- Проверить `/health` на master-node (9090)
- Проверить `/health` на каждой storage-node (8085, 8086, ...)

### 2. Управление storage-ноды (через мастер-ноду)
- Зарегистрировать новую storage-node (POST /scheme)
- Проверить, что нода отображается в /scheme
- Удалить storage-node (DELETE /scheme/{server})
- Проверить, что нода удалена из /scheme

### 3. Шардирование
- Изменить количество шардов (PUT /shards)
- Проверить, что схема обновилась (GET /scheme)

### 4. CRUD операции с данными
- Положить значение на ключ через мастер/прямо в storage
- Проверить, что значение читается
- Изменить значение, проверить апдейт

### 5. Миграция и масштабирование
- Записать данные, добавить новую storage
- Изменить шардинг, проверить миграцию (ключи доступны)
- Удалить storage, проверить что данные не потеряны

### 6. Отказоустойчивость
- Остановить storage, попробовать удалить её через мастер, убедиться что система не падает

### 7. Проверка версий storage (GET /storage/version)

### 8. Массовые сценарии
- Зарегистрировать несколько storage подряд
- Провести CRUD по множеству ключей, сменить шардинг, убедиться что данные не потеряны
